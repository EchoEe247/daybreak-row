# Daybreak Row — full repository and development audit

**Audit date:** October 17, 2026 (America/Chicago).  
**Repository:** EchoEe247/daybreak-row  
**Source baseline:** `577cf0b82dd8ceccdcbe6863306f6148405fe90e` (`fix: audit all game asset placements and interaction clearance`). GitHub and the clean Termux checkout matched.  
**Scope:** gameplay, input/UI, saves/economy/time, renderer/asset lifecycle, asset provenance and placement process, checks/build/runtime, documentation, repository controls and maintenance.  
**Change scope:** audit documents/evidence only; no game code, assets, dependencies, deployment, visibility or normal player-save changes.

## Assessment

Daybreak Row has a working mobile-oriented game foundation: five districts, nine interiors, licensed bundled characters/environment assets, fixed daylight, needs/economy, daily routes and discovery. The game tests and build pass. However, save failures can go unnoticed, malformed saves are accepted, keyboard menu state can freeze play without displaying the menu, and the development process has no enforced automated gate. Reliability and repeatable device QA should precede another large content expansion.

This is an audit of the pinned snapshot, not an assurance that every camera angle, model, animation frame or device condition is correct. Findings distinguish reproduced behavior, source-confirmed defects and missing verification.

### F01 — Validate complete saves and recover without discarding progress

**Evidence:** [store.ts, loadSave](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/store.ts#L88) accepts JSON after checking only `version === 1` and numeric money. [engine.ts, begin/sync](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/engine.ts#L235) and [discovery.ts](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/discovery.ts#L11) immediately depend on needs, log, place, coordinates and other fields.

**Reproduction:** supplying `{"version":1,"money":186}` returns a non-null save. Accessing `saved.log.slice(...)` then throws. The browser fault probe also accepted that object. Other malformed fields, including invalid place IDs, nonnumeric coordinates or invalid optional arrays, are not normalized or rejected.

**Impact:** damaged, edited or incompatible local data can prevent Continue from working. The visible recovery path currently includes erasing the life.

**Fix:** introduce a version-1 parser with complete structural validation, finite/ranged numbers and a known-place whitelist. Default only documented optional legacy fields. Retain a last-known-good backup and offer recovery/export before any destructive reset.

**Acceptance:** valid legacy fixtures preserve money/needs/relationships and coordinates; truncated JSON, missing required fields, invalid place, null/invalid arrays and nonfinite/out-of-bounds coordinates produce a recoverable result without overwriting the original data.

### F02 — Surface failed writes rather than marking them saved

**Evidence:** [store.ts, writeSave](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/store.ts#L101) catches all failures without returning a result. [engine.ts, remember](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/engine.ts#L281) still updates `saved` and `saveMinute`. The pause menu says “Save and return.”

**Reproduction:** make `Storage.prototype.setItem` throw a quota/security exception in an isolated session. `writeSave` reports no failure to its caller. Both the source harness and browser fault probe reproduced this.

**Impact:** the current session can offer Continue even when no durable state was written; closing the browser loses that progress.

**Fix:** return an explicit success/error result, retain the unsaved/dirty state, and display a useful persistence warning with retry/export. Keep the previous valid save until the replacement succeeds.

**Acceptance:** injected storage failure is visible; it does not advance the last-successful-save marker, and a retry persists correctly. Verify ordinary saves and reloads still work.

### F03 — Synchronize keyboard-triggered menu transitions

**Evidence:** [input.ts](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/input.ts#L78) queues KeyP/Escape. [engine.ts, tick](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/engine.ts#L580) changes internal mode to phone/pause without calling `sync`; the periodic [sync condition](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/engine.ts#L787) excludes those modes. Button-driven APIs call `sync(true)`, so touch buttons follow a different path.

**Browser observation:** internal mode became `pause`, while the DOM still showed the ordinary HUD, Run and Use. There was no “Paused” card or Resume button. The harness timed out looking for Resume. The test was resumed through the actual game API before continuing the doorway checks.

**Impact:** keyboard users can freeze gameplay without an explanation or visible resume action. KeyP has the same synchronization defect. Subsequent keyboard events in phone/pause are discarded rather than toggling the menu.

**Fix:** route keyboard and button actions through one mode-transition function, clear held input consistently and synchronize immediately. Define Escape to close phone/pause and P to toggle phone.

**Acceptance:** real keyboard Escape and P display the correct overlay and close it predictably; touch buttons remain correct; movement does not remain held across a menu transition.

### F04 — Invoke actor cleanup and define resource ownership

**Evidence:** [actors.ts, Actor.dispose](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/actors.ts#L228) sets the disposed flag and stops/removes loaded rigs. [engine.ts cleanup](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/engine.ts#L797) disposes world/global actor materials and renderer, but never calls `player.dispose()` or any named NPC's `dispose()`.

**Impact:** late human-loader promises can attach after the mount has been abandoned, and the intended per-actor mixer cleanup is skipped. This is source-confirmed; a quantified retained-memory increase was not measured.

**Fix:** dispose every owned actor before renderer/material teardown. Document which cached geometry/material/texture resources are shared versus mount-owned. Clear mount-owned timers and prevent late callbacks from modifying disposed scenes.

**Acceptance:** repeatedly mount/unmount, including unmount before models resolve; no late scene attachments or active actor mixers remain, and resource counts/heap settle to a documented stable range.

### F05 — Restore one meaningful green check command

**Evidence:** [package.json](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/package.json#L10) makes `npm test` run script fixtures, then the TypeScript tests with `&&`. It does not include the `src/game` suite. Ten script tests currently fail: two inherited branding-instruction assertions and eight PWA/OG identity assumptions. Lint errors are at [human-assets.test.mjs:1](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/human-assets.test.mjs#L1) and `src/lib/app-data/client.server.ts:281`.

**Impact:** a contributor running the conventional command sees an accepted failure baseline, does not run the remaining stage, and does not test most gameplay.

**Fix:** isolate PWA fixtures from the repository's actual site metadata; revise obsolete scaffold instruction assertions to test supported behavior. Fix the two lint errors. Add a documented aggregate command that includes gameplay, retained framework tests, typecheck, lint and build, with independent stage reporting.

**Acceptance:** the aggregate command is green on a clean install and fails on a deliberately introduced gameplay regression. Preserve useful framework/auth tests rather than deleting them solely to obtain a green result.

### F06 — Add an enforced repository gate

**Evidence:** the complete tree has no `.github/workflows/`; GitHub Actions returned zero runs. GitHub's branch response reports `main.protected=false`, and repository rulesets returned an empty list. There are no PRs, issues, releases or local tags at this snapshot. The detailed protection endpoint was unavailable to the integration; no additional administrative settings are inferred.

**Impact:** direct changes can land without any automatic build, test or asset-integrity gate. Documentation is currently carrying the burden of remembering every manual check.

**Fix:** add CI after F05 is green, using a validated Node version and `npm ci`. Require the aggregate check for changes to main. Use reviewable branches/PRs and tag the first verified playable baseline.

**Acceptance:** an intentionally failing PR is blocked; game, runtime, asset and documentation changes trigger the relevant checks. Keep branch-policy changes separate from this audit.

### F07 — Preserve the tooling that produced the evidence

**Evidence:** [browser-smoke.mjs](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/scripts/browser-smoke.mjs#L1) imports Playwright directly and restricts output locations to `/workspace`, while the real project runs in Termux. Native invocation rejected Android in this audit. The [placement report](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/docs/research/ASSET-PLACEMENT-AUDIT-2026-10-17.md) describes AABB/grid-reachability checks, and [integration/provenance](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/docs/research/REALISM-INTEGRATION-2026-10-17.md) describes extracted/optimized GLBs, but the repository does not contain the corresponding complete placement traversal or asset-conversion recipes.

**Impact:** a future contributor can verify current hashes but cannot reproduce the key spatial checks or rebuild the optimized pack using the repository alone. This increases dependence on chat history and one local workspace.

**Fix:** retain bounded scripts/configuration for GLB extraction/optimization, scene-bound checks, collision-aware action reachability, and isolated browser input/save/door tests. Use relative/configurable workspace paths, explicit supported execution environments, deterministic seeds and commit-bound evidence.

**Acceptance:** another checkout can run the documented recipe, reproduce equivalent asset metadata and discover an intentionally blocked action without access to the original chat. Compare normalized content where byte-for-byte export is nondeterministic.

### F08 — Ignore local secret files and add a repeatable scan

**Evidence:** [.gitignore](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/.gitignore) omits environment-file patterns. `git check-ignore --no-index .env .env.local .env.production` returned status 1 with no matches.

**Impact:** a routine `git add .` can include future credentials. No leaked credential is asserted: the limited current-tree token-pattern scan found none, and no tracked .env file appears in the snapshot.

**Fix:** ignore `.env` and `.env.*`, retain a deliberately sanitized example with an exception, and add a maintained current/history secret-scan procedure.

**Acceptance:** local env examples with fake values remain ignored; the sanitized template is trackable; the chosen scan detects a seeded fake token in a test repository without exposing actual secrets.

### F09 — Verify game identity in the launcher

**Evidence:** [start-local.sh:6–8](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/start-local.sh#L6) accepts any successful HTTP HEAD response. A temporary unrelated HTTP server on an isolated ephemeral port caused the unchanged launcher to print “Daybreak Row already running” and exit 0.

**Impact:** a port collision can send the user to another service while the launcher reports success.

**Fix:** probe a stable app identity/build endpoint, validate ownership before reusing a process, and report a port conflict explicitly. Make the auth-check URL follow the selected runtime port; the default 8080 probe currently checks a different endpoint from the owner's 4186 game.

**Related runtime observation:** `npm run dev` and Vite bind `0.0.0.0`; the phone URL is localhost, but the server is configured to listen on all interfaces. Use a loopback default for phone-only play and opt into LAN access deliberately. No successful outside connection was tested.

**Acceptance:** a wrong service is rejected, the correct running game is reused, and the requested port and auth probe agree.

### F10 — Make inherited remote platform code an explicit choice

**Evidence:** [grok-pwa-shared.mjs:203–247](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/scripts/grok-pwa-shared.mjs#L203) defaults `VITE_GROK_EXTENSIONS` to enabled and injects `https://grok.com/grok-app-builder/extensions.js`. The running isolated page's script list confirmed it. [__root.tsx](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/routes/__root.tsx#L27) also requests Google Fonts, with local font fallbacks.

**Impact:** the local game still executes a remotely supplied platform script outside the original sandbox. This creates an extra network/trust dependency; remote code in the page has the normal page privileges. No malicious behavior or data disclosure was observed.

**Fix:** decide whether that platform banner/extension is needed in the local product; if not, use the existing opt-out in the local launch/build contract. Document fonts/network fallback and keep platform-specific behavior behind explicit configuration. Review export terms before removing anything contractually required.

**Acceptance:** a clean local launch has only intended script/network origins, preserves saves and gameplay, and remains usable with external networking blocked.

### F11 — Establish a real mobile acceptance baseline before further expansion

**Evidence:** [RUNTIME-AND-QA.md](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/docs/handoff/RUNTIME-AND-QA.md) correctly admits that sustained physical Pixel 6a FPS/frame times, memory, thermals, battery and comprehensive touch comfort are unverified. This audit used dedicated Chromium, not the owner's physical Chrome gameplay profile. The isolated software run reported 84 draw calls, 263,596 triangles and 63 renderer-tracked textures at the initial harbor view; the laundry entry reported 108 draw calls and 189,712 triangles. Renderer-tracked textures reached 232 after the nine-room tour. These are sampled renderer counters, not physical GPU memory in bytes, FPS measurements or proof of a leak.

The current `public/` tree contains 119 files totaling 50,287,619 bytes (about 48.0 MiB): humans 8,516,014 bytes; environment 41,347,923 bytes. These are repository payload totals, not the initial network transfer. The production engine chunk is about 753.86 kB minified / 201.43 kB gzip. Demand loading and caches exist; full-world unload/eviction and a measured device budget are not established.

**Impact:** more realistic assets can improve visuals while causing sustained-play regressions that the current checks cannot detect.

**Fix:** define an owner-approved provisional performance target, then measure it on the real phone: cold/warm start, harbor/downtown, each interior, a full tour, multitouch while turning/interacting, background/resume, and a sustained session. Record browser/build identity, frame-time distribution, resource counts and device conditions. Turn the observed baseline into a regression budget.

**Acceptance:** a repeatable physical-device report exists and a representative content increase is compared against it. Software renderer statistics must remain labeled separately.

### F12 — Align gameplay rules with labels and shared time helpers

Three lower-priority inconsistencies were reproduced:

1. **Bed:** [logic.ts:265–268](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/logic.ts#L265) labels Nap only above energy 55, but runs a nap above 50. At noon with energy 53, the UI label is **Sleep** while the result is **nap**. Derive label and action from one predicate.
2. **Collapse cooldown:** [engine.ts:649–650](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/engine.ts#L649) uses `day*1440+minute`, while [time.ts:20–21](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/time.ts#L20) and [collapse](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/logic.ts#L1079) use `(day-1)*1440+minute`. Immediately after a collapse, the guard computes 1,440 elapsed minutes rather than zero. Use `absMinute` consistently. Ordinary post-collapse energy recovery may mask the error, so this is not described as an observed collapse loop.
3. **Work cooldowns:** [desk](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/logic.ts#L329) sets `freelanceAt=now+70` and advances 80 minutes; [city office](https://github.com/EchoEe247/daybreak-row/blob/577cf0b82dd8ceccdcbe6863306f6148405fe90e/src/game/logic.ts#L892) treats the same field as the last-work timestamp, checks 120 minutes and advances 125. Both can pay on the immediately following activation, subject to energy. Confirm whether cooldowns mean time since work started or time after completion, then use distinct clearly defined fields if needed. Repeated paid work is not itself a demonstrated exploit because it consumes game time and needs.

**Acceptance:** boundary tests cover energy 50/53/55/56, midnight, cooldown completion and switching between the two work activities while preserving existing version-1 saves.

## What is already good

- The handoff docs explicitly identify Termux, the correct phone URL, nine interiors, intentionally fixed visual daylight and the limits of software-WebGL QA.
- The owner’s normal browser saves are separate from Git; version 1 has backward-compatible optional fields.
- Asset manifests retain source URLs/licenses/hashes; the game suite verifies bundled environmental assets and expected human structures/notices.
- Tree batching, reduced mobile car/vegetation counts, deferred nearby/room prop loading and lower touch-render settings show deliberate resource management.
- Touch controls have pointer ownership/cancel handling, and the isolated browser confirmed combined joystick/Run and camera input.
- Clean checkout, lockfile, readable game/scaffold separation and dated implementation reports provide a useful starting point.
- No general original-code license is declared, and README accurately says public visibility does not grant reuse rights. This audit does not change that decision.

## Recommended order of work

| Order | Deliverable | Completion condition |
| --- | --- | --- |
| 1 | Save validation/recovery and write-failure reporting | Malformed and storage-denied cases recover safely; valid legacy saves remain intact |
| 2 | Keyboard/UI state and actor lifecycle fixes | Keyboard/touch use the same transitions; repeated remount/late-load checks pass |
| 3 | Green aggregate checks and basic repository hygiene | All supported checks pass; env files ignored; correct runtime URL used |
| 4 | CI and review/release baseline | Failing changes are gated; known playable commit tagged |
| 5 | Retained browser, spatial and asset-build recipes | Reproducible on documented supported environments |
| 6 | Physical Pixel baseline and resource budgets | Sustained real-device report with repeatable acceptance criteria |
| 7 | Gameplay consistency, then focused art/content work | F12 fixed; one coherent district/interior pilot improves realism within measured budgets |

Architecture changes should be incremental. `engine.ts` currently owns rendering, simulation, menus, saving and transitions; `logic.ts` mixes activity definitions, economy, dialogue and time rules. Extract persistence and mode transitions first because the reproduced bugs identify useful boundaries. Move venue definitions into typed shared data after behavior is covered, rather than rewriting the whole game.

For the next visual pass, prioritize consistent architecture/material scale, shop contents, indoor lighting and believable activity/animation. The inspected harbor/market captures still mix realistic humans/photo textures with simple architecture and sparse displays. Those are art-direction observations from sampled views, not proof that all assets need replacement.

## Repository and delivery state

- Repository visibility was **public** during this audit, consistent with the documented temporary external-research setup. Visibility was not changed.
- No public game deployment/homepage is configured in the repository metadata; the on-phone localhost address remains device-local.
- No CI workflows, releases, tags, issues or PRs existed at the audited baseline. This report's documentation branch/PR is subsequent audit output, not part of the baseline.
- The existing `docs/claude/` research/roadmap templates remain marked NOT STARTED. This audit does not claim Claude completed them.
- Pin a supported Node/npm recipe or version file, give the package a project-specific name, and document clean-install validation. This run used existing installed dependencies; `npm ci` from a fresh checkout was not repeated.
- Retain screenshots/evidence only when tied to a commit, viewport and renderer. Keep historical reports labeled and link current summaries to the newest verified evidence.

## Limits and outstanding verification

No source fixes were applied. This audit did not certify physical-device performance, exhaustive asset placement/reachability, every paid activity and dialogue branch, full Git-history secrets, external-script behavior, all inherited auth/database code paths, a production deployment, or independent licensing provenance for every upstream asset. Existing placement claims were inspected but the predecessor's complete grid/AABB procedure was not available as a retained repository script. The browser tour used deterministic QA positioning to exercise doors; it does not prove every walking route is reachable.

The bounded browser runs and fault probes used isolated browser storage. The owner’s ordinary Chrome profile and saved game were not cleared or modified. The adjacent [audit evidence JSON](AUDIT-2026-10-17-evidence.json) preserves check results, browser observations and reproduction summaries.
